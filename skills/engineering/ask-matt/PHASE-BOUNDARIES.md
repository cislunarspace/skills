# 阶段边界

一个**阶段（phase）** 是一次会话里的一块工作——质询、实现、QA。定义故意模糊：一个阶段结束于你想"好，这块完了"的那一刻。

**阶段边界** 是两个阶段之间的间隙，而这个决策只该在这里做。阶段中间没什么决策要做——继续，或把剩下的工作拆成子代理。阶段中间 compact 会让 agent 丢线。

## 五个选项

| 选项 | 做什么 |
| ------------ | --------------------------------------------------------------- |
| **Continue（继续）** | 待在会话里。完全没有上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可移植的 markdown 文件，用它给任意地方的新会话播种。 |
| **Subagent（子代理）** | 把任务送到它自己的上下文窗口，拿回一份报告。 |
| **`/compact`** | 压缩这份上下文，用摘要给一次新会话播种。 |

## 决策树

在边界上自上而下走。第一个 **是** 胜出。

**1. 能在本次会话里继续吗？** 两件事让答案为是：下一阶段需要本阶段作为**一手资料**，或你剩下的 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（~150k token）还够下一阶段装。质询 → 实现是标准的"是"：实现要的是推理本身的原话，不是它的摘要。Continue 不花什么也不丢什么，所以先排除它再谈别的。

**2. 上下文对接下来无关吗？** 本次会话里的一切——探索、决策、死胡同——都可丢弃吗？如果是，**`/clear`**。它是棋盘上最便宜的一手：不花时间，退回整个窗口。`/clear` 也不是终局——旧会话仍可恢复。

搞错的成本是单向的。clear 掉一个*相关*的上下文，你就丢了你构建之物背后的**为什么**，再怎么读回 diff 也拿不回来。

**3. 需要交班吗？** `/handoff` 是窄的。你只在以下情况需要它：

- 换到**新 harness**（Claude → Codex），
- 移到**新目录**或仓库，
- 把工作发给**同事**，
- 或阶段中 fork 一个你发现的支线任务、不打断手头的事。

这张清单就是全部条款。`/handoff` 买的是**可移植性**——一个能走的文件。没什么在走，就不需要它。

**4. 任务能 AFK 做吗？** 它范围够紧、能让你离开键盘跑、无需转向吗？那就把它发给一个**子代理**，本次会话原封不动。自动评审是标准情形：agent 读 diff 并汇报，它做的时候不需要你。

**5. 否则，`/compact`。** 相关上下文、同一 harness、同一目录、而你需要留在回路里——树就落在这里，而且常常落在这里。传给它一条指令（`/compact 我们接下来要 QA 这片区域`），好让摘要保住下一阶段需要的东西。

`/compact` 是**默认项，不是第一选择**。它在最底下，因为上面四个问题都更便宜或更精准。人们从这里起步的失败模式是：一次新会话对一个被摘要压平的决策自信地错了。

## 一手资料和二手资料

除 **Continue** 外的每一步都把**一手资料**变成**二手资料**——会话本来的样子，被它的摘要取代。交易总是同一个形状：

| 资料 | 信息 | 噪声 | 回旋余地 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（Continue） | 全 | 多 | 少 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 多 |

这就是为什么问题 1 排第一。只有在留下的成本大于它省下的时候，你才付有损的代价。

## 这些是判断题

这些问题不客观——每个里都有口味，同一个边界两天能走两条路。价值在于**按顺序**、在边界上而不是工作中间问它们。
