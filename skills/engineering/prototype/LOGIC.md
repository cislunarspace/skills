# 逻辑原型

一个自包含的 HTML 文件——一份**可分享的演示**——让任何人都能通过点按钮来驱动一个状态模型。当问题是关于**业务逻辑、状态转换或数据形状**时用这个——那种在纸上看着合理、但只有真用实际例子推一遍才觉得不对的东西。

因为它是一个无需安装的文件，你可以把它交给非开发者——设计师、PM、领域专家——让他们自己感受这个模型。所以它说他们的语言，不是说代码的语言。

## 什么时候该用这个形状

- "我不确定这个状态机能不能处理 X 然后 Y 的边界情况。"
- "这个数据模型到底能不能表示……那种情况？"
- "我想先摸清楚 API 应该长什么样，再动手写。"
- 任何有人想**按按钮、看状态变**的场合。

如果问题是"这东西应该长什么样"——走错路了。用 [UI.md](UI.md)。

## 流程

### 1. 把问题说出来

写代码之前，先写下你要原型化的是什么状态模型、什么问题。一段话，放在演示顶部（可见的介绍里，不只是注释）。一个回答错了问题的逻辑原型是纯浪费——把问题写明，好让后面能检查它答得对不对，不管用户现在在看着还是回头来看。

### 2. 把逻辑隔离进一个可移植模块

把真正的逻辑——回答问题的那段——放在一个 `<script>` 块里，写成一个小的、纯的模块，日后可以被拎出来、丢进真实代码库。它外面的页面是一次性的；这个模块不是。

合适的形状取决于问题：

- **一个纯 reducer** ——`(state, action) => state`。动作是离散事件、状态是单值时好用。
- **一个状态机** ——显式的状态和转换。"当下哪些动作合法"本身就是问题的一部分时好用。
- **一组小的纯函数**，作用在一个朴素数据类型上。没有隐式的当前状态、只有变换时好用。
- **一个类或模块，带清晰的方法面** ——当逻辑确实持有持续内部状态时。

选最贴合所问问题的形状，*不是*最好往页面上接的形状。保持纯净：不碰 DOM、不碰 `document`、没有按钮处理函数伸进它里面。页面调用它；没有东西反向流回来。正是这一点让原型在它自己的生命周期之外仍然有用：问题答完之后，经过验证的 reducer / 状态机 / 函数集自己就能拎进真实模块。

### 3. 搭这个可分享的 HTML 文件

一个文件，纯 HTML/CSS/JS——不用框架、不用 bundler、不用服务器，所有东西内联，双击即开、经得起邮件传来传去。任何人都应该能靠打开它来运行。

为非开发者写。每个标签都用**领域语言**，不是代码——按钮和状态读起来像业务，不是 reducer。用平实的话解释正在发生什么。

自上而下，用清晰的层次铺开：

1. **标题和一行说明**，说这个演示能让你探索什么（第 1 步的那个问题）。
2. **当前状态** ——完整的相关状态，渲染成一个可读的面板（带标签的字段，不是原始 JSON 转储），每次点击后重新渲染，让变化看得见。在能帮非开发者跟上的地方，点出刚刚变了什么。
3. **自由按钮** ——每个动作一个按钮，始终可用，让任何人都能以任意顺序戳这个模型。每次点击派发它对应的动作并重新渲染状态。
4. **引导走查** ——一组**场景**，一个分页一个。每个分页先放这个场景的简短平实描述——它设的情境、要看什么——下面是该场景要按的、排好序的**按钮**。每一步是一个真正的按钮：点它就执行那个动作并走到下一步。开始一个走查会重置到一个已知的初始状态，让场景每次都一样地跑。

挑那些能展示棘手情况的场景——happy path、一个刁钻的边界情况、一个想做但不该合法的尝试——那些纸上难推演的。

让它漂亮但克制：干净的字体、慷慨的间距、一个强调色。不要动画、不要花活——别让任何东西跟状态和按钮抢戏。

### 4. 交接

把文件发给他们，或替他们打开。他们会在方便时点过走查和自由玩；有意思的时刻是当他们说"等等，这不该可能"或"咦，我以为 X 会不一样"——那些是_想法里_的 bug，而这正是全部意义所在。他们想要新动作或新场景，就加。原型会演化。

### 5. 记下答案和原型

原型回答完它的问题后，记下答案，然后按 [SKILL](SKILL.md) 描述的方式留存原型。逻辑相关的映射：经过验证的 reducer / 状态机 / 函数集拎进真实模块（决策，吸收了）；HTML 外壳跟着上那个一次性分支，让原型作为一手资料留在那里——而作为一个自包含文件，它在那边仍然可以轻松重跑。

## 反模式

- **别加测试。** 需要测试的原型就不再是原型了。
- **别接到真实数据库上。** 用内存状态，除非问题明确是关于持久化的。
- **别泛化。** 不要"万一以后想支持 X"。原型回答一个问题。
- **别把逻辑和页面糊在一起。** 如果纯模块引用了 DOM、`document` 或按钮处理函数，它就不再可拎了。让页面保持为一个薄壳，罩在纯模块外。
- **别上框架、bundler 或服务器。** 接收者双击打开的一个文件；React 应用或 dev server 毁掉"可分享"。
- **别把 HTML 外壳发到生产。** 页面是为被人手点过而优化的。它背后的逻辑模块才是值得保留的那部分。
